# PyGeoTrack — симулятор движения

Готовое локальное desktop-приложение для демонстрации движения грузовика по автомобильному маршруту: карта, цифровой профиль рельефа, имитация CAN, физический расход топлива, восстановление высот и прогноз уклона средствами ML.

Интерфейс построен на **PySide6 + QWebEngineView + Leaflet + PyQtGraph**. Отдельный браузер не используется. Код и данные никуда не публикуются. Для нового маршрута координаты отправляются OSRM и Open-Meteo; для подложки карта запрашивает тайлы OpenStreetMap.

## Быстрый запуск

В этом рабочем каталоге уже подготовлена `.venv` и установлены зависимости. Windows PowerShell:

```powershell
cd E:\PyGeoTrack
.\.venv\Scripts\python.exe main.py
```

Также можно дважды щёлкнуть **run.bat**. Он активирует локальную `.venv`, переходит в каталог проекта и запускает приложение. Если окружения нет, выводит команды установки.

На компьютере, где Python доступен в PATH, после активации окружения основная команда — `python main.py`.

### Установка на другом компьютере

Рекомендуется 64-битный Python 3.11 или 3.12 и Windows 10/11. Проверено на Windows с Python 3.12.14.

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

Для PowerShell можно обойти ограничения ExecutionPolicy, не активируя окружение:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

`requirements.txt` задаёт совместимые диапазоны, `requirements-lock.txt` фиксирует фактически проверенное окружение Python 3.12. Для его воспроизведения установите `-r requirements-lock.txt`. Не переносите `.venv` между компьютерами: создайте её заново.

Linux: `python3 -m venv .venv`, `source .venv/bin/activate`, затем те же команды pip и запуска. Нужны системные библиотеки Qt/WebEngine, рабочий графический сеанс и драйверы. GUI проверен на Windows; отдельная проверка Linux не проводилась.

## Демонстрация

В комплекте **реальный маршрут Туапсе → Сочи, Россия**, полученный OSRM, и реальные высоты Open-Meteo / Copernicus DEM GLO-90:

| Параметр | Значение |
|---|---|
| A, запрошенные latitude / longitude | 44.09640 / 39.07470 |
| B, запрошенные latitude / longitude | 43.58550 / 39.72310 |
| Длина по геодезическим сегментам геометрии | 119,01077 км |
| Полная геометрия | 4562 точки |
| Ресемплированный профиль | 1192 точки, шаг 100 м и последний остаток |
| Сглаженная высота | около 4–211 м |
| Полная масса | 14 000 кг: автомобиль 9 000 + груз 5 000 |

OSRM привязывает A/B к доступной дороге: фактическая конечная точка — 43.585295 / 39.723710. Карта показывает эти дорожные точки. Длина OSRM и сумма Haversine могут немного различаться; симуляция использует последнюю.

1. Откройте приложение; подготовка CSV и ML идёт в фоне.
2. Нажмите **СТАРТ**. Зелёный след показывает пройденный путь; голубой — весь маршрут.
3. Выберите ×1, ×2, ×5, ×10 или ×20.
4. **ИИ-УПРАВЛЕНИЕ СКОРОСТЬЮ** плавно изменяет скорость к рекомендации; выключите его для ручной установки скорости 30–90 км/ч.
5. **ПАУЗА** замораживает модель и время; **СТАРТ** продолжает.
6. **СБРОС** обнуляет время, путь, топливо, CAN-файл, движущиеся графики и возвращает автомобиль в A. Полные фоновые профили и отметки восстановленных высот сохраняются.
7. В B автомобиль останавливается, появляется итог с временем, расстоянием, расходом и средней скоростью.
8. Введите другие координаты и нажмите **ПОСТРОИТЬ МАРШРУТ**, чтобы запросить новую дорогу и высоты. При ошибке API статус и поля показывают фактически загруженный локальный маршрут.

Интерфейс, сообщения, единицы измерения, подсказки карты и стандартные действия Qt переведены на русский. Имена библиотек, технические имена файлов/столбцов CSV и названия API сохранены. Поля скорости и координат имеют отдельные зоны стрелок 28×18 пикселей. Окно адаптивное; минимальный размер 1200×750. При небольшой высоте правая панель прокручивается. На графике высоты золотые точки восстановлены ML; фиолетовый ромб на графике уклона — прогноз на 300 м вперёд. В последних 300 м прогноз скрывается, поскольку горизонт выходит за B.

## Архитектура

```text
main.py                  создание QApplication и logging
config/settings.py       пути, координаты, параметры физики/API/симуляции
services/
  http_client.py         timeout, 3 попытки, проверка JSON/HTTP
  route_service.py       OSRM driving, GeoJSON и время/длина
  elevation_service.py   Open-Meteo, пакеты до 100 координат
  route_processor.py     Haversine, ресемплинг, уклоны, проверка CSV
  pipeline.py            cache → API → fallback → ML → CSV
  can_simulator.py       CANData и поток записи CSV
models/
  fuel_model.py          физическая модель продольных сил
  speed_optimizer.py     численный поиск оптимума по сетке скоростей
  curve_speed.py         кривизна дороги и заблаговременное торможение
  terrain_restorer.py    ExtraTreesRegressor для восстановления высот
  slope_predictor.py     RandomForestRegressor для будущего уклона
simulation/
  vehicle_simulator.py   VehicleState, интегрирование движения, итог
ui/                      окно, worker QThread, dashboard, графики и стили
map/                     HTML, Python bridge, локальные Leaflet JS/CSS
data/                    рабочие CSV, GeoJSON, метаданные, ML-метрики
data/demo/               отдельная резервная копия реального маршрута
scripts/                 подготовка данных и GUI smoke test
tests/                   тесты бизнес-логики и отказов API
```

Все пути вычисляются от расположения файлов проекта, а не от текущей директории. HTTP, обработка данных, обучение ML и подготовка рекомендаций выполняются в `QThread`. Взаимодействие с виджетами — через Qt signals в основном потоке. При закрытии во время сетевой загрузки окно ждёт завершения ограниченных timeout-запросов, не уничтожая работающий поток.

`QTimer` обновляет интерфейс каждые 100 мс. Время измеряется `perf_counter`, умножается на масштаб, затем разбивается на шаги до 0.2 с. Путь интегрируется по средней скорости с ограничениями +1.0 / −1.5 м/с²; перед B действует торможение. Последний шаг усекается по точному оставшемуся расстоянию. При длительной задержке GUI учитывается не более 0.5 с реального времени за обновление, чтобы избежать скачка автомобиля после перемещения окна/возобновления сеанса.

Профиль хранится в памяти; карта и графики создаются один раз. ML не обучается на тиках. Рекомендации рассчитываются по точкам при загрузке и интерполируются с ограничением изменения 3 км/ч в секунду. Автомобиль движется по **полной исходной геометрии**, поэтому не срезает повороты между 100-метровыми точками профиля.

## API, локальные данные и offline

- [OSRM Route API](https://project-osrm.org/docs/v5.24.0/api/): `https://router.project-osrm.org/route/v1/driving/...`, `geometries=geojson`, `overview=full`. Геометрия в порядке longitude, latitude.
- [Open-Meteo Elevation API](https://open-meteo.com/en/docs/elevation-api): `https://api.open-meteo.com/v1/elevation`; до 100 координат в запросе, DEM GLO-90 с разрешением около 90 м.
- [OpenStreetMap](https://www.openstreetmap.org/copyright): стандартные тайлы внутри Leaflet, атрибуция на карте. Автоматическая массовая загрузка тайлов не выполняется.
- [Leaflet 1.9.4](https://leafletjs.com/download.html): JS/CSS включены локально; BSD-лицензия в `map/vendor/LICENSE`. Маркеры — divIcon, внешние изображения не нужны.

Базовая демонстрация не требует API-ключа. Публичные сервисы имеют ограничения использования; проект рассчитан на учебную демонстрацию, а не массовую коммерческую нагрузку.

При `USE_CACHED_ROUTE = True` (по умолчанию) загрузка использует `data/route_original.csv`. **ПОСТРОИТЬ МАРШРУТ** принудительно обращается к API. При сбое маршрута или высот загружается целый прежний маршрут: высоты от другого маршрута к новой геометрии не подмешиваются. Если основной CSV повреждён, используется `data/demo/`. Эти резервные данные получены настоящими API, синтетические высоты в комплекте не используются.

Если нет тайлов, Leaflet продолжает показывать маршрут, A/B, автомобиль и след на однотонном фоне с сообщением. Если повреждены локальные файлы Leaflet, HTML показывает схему маршрута на canvas. Если отсутствует сам HTML, dashboard и симуляция продолжают работать с сообщением в строке состояния.

Для подготовки данных без GUI:

```bat
python -m scripts.prepare_data
python -m scripts.prepare_data --refresh
```

Вторая команда запрашивает маршрут по умолчанию из settings и обновляет рабочие файлы. Снимок `data/demo/` автоматически не изменяется.

Для длинных маршрутов запросы высот разделены паузами 11 с. Ответы на пакеты сохраняются в `data/elevation_cache/` по хешу URL и точных координат: повторная загрузка использует уже полученные значения. При HTTP 429 учитывается Retry-After с ограниченным ожиданием и повторами. Первая загрузка нового маршрута около 100 км может занять несколько минут; штатный запуск поставляемого маршрута не требует этих запросов.

## Формат данных

CSV — UTF-8, десятичный разделитель точка; реальные пропуски сохраняются пустыми CSV-полями и читаются pandas как NaN. Запись через временный файл с заменой.

| Файл | Содержание |
|---|---|
| `route_original.csv` | Проверенный профиль: исходные DEM-высоты и обработанные высоты/уклоны |
| `route_missing.csv` | Несколько блоков 3–8 точек с удалёнными высотами; NaN-уклоны там, где нет исходной пары высот |
| `route_restored.csv` | Восстановленные высоты, пересчитанные уклоны, прогнозы |
| `route.csv` | Активный профиль симуляции, копия restored |
| `can_data.csv` | Начальная запись и телеметрия каждого обновления; RESET начинает файл заново |
| `route_geometry.geojson` | Полная дорожная LineString от OSRM |
| `route_metadata.json` | Название, координаты, длина/длительность OSRM, источники |
| `ml_metrics.json` | Реальные результаты валидации текущего маршрута |

Обязательные колонки профиля: `point_id`, `latitude`, `longitude`, `segment_distance_m`, `total_distance_m`, `elevation_m`, `slope_pct`.

Дополнительные: `elevation_raw_m` (сырой DEM), `slope_raw_pct` (до ограничения), `slope_angle_deg`, `is_restored` (0/1), `predicted_slope_pct`, `prediction_available`. После восстановления `elevation_raw_m` остаётся пустой в скрытых точках — это источник, а не оценка модели.

Расстояния ресемплинга — длины вдоль исходной дорожной полилинии, посчитанные Haversine. В поворотах они больше прямой хорды между двумя точками. Уклон `100 * Δh / Δs`; в первой точке 0, деление на ноль защищено. Исходные высоты сглаживаются причинным средним по текущей и двум предыдущим точкам. Демонстрационный уклон ограничен ±25%; рассчитанный до ограничения уклон сохранён отдельно. Сглаживание не берёт будущие точки, чтобы не допускать утечки в ML.

CANData: `speed_kmh`, `vehicle_mass_kg`, `cargo_mass_kg`, `total_mass_kg`, `simulation_time_s`. Это имитация параметров, не драйвер физического CAN-адаптера и не DBC-декодер.

## Машинное обучение

### Восстановление рельефа

Генератор с seed 42 удаляет **20% высот** с округлением числа строк: на демонстрационном маршруте **238 из 1192 точек**. Участки состоят из нескольких последовательных пропусков (обычно 5–6 точек), разделены известными точками; начало и конец сохранены. Число удалённых строк точно равно `round(N × 0.20)`. Доля задаётся `MISSING_ELEVATION_FRACTION` в settings. Сырые высоты тоже скрываются в этих строках. `ExtraTreesRegressor` (120 деревьев) учится на latitude, longitude и пройденном расстоянии, target — обработанная elevation_m. Никакая интерполяция не выдаётся за восстановление ML.

Валидация удерживает блоки по четыре известные точки. Метрики считаются до повторного обучения на всех известных точках. Это проверка пространственного восстановления внутри известного маршрута, не проверка переноса в другой регион. Значения известных высот модель не изменяет. Если все высоты отсутствуют, модель явно сообщает об отсутствии обучающих данных.

### Прогноз уклона

`RandomForestRegressor` (100 деревьев) обучается на исходном профиле. Признаки: текущий уклон, три лага уклона, изменения высоты за 1/3/6 точек, причинное среднее и стандартное отклонение уклона. Абсолютные GPS-координаты в эту модель не включены, чтобы уменьшить запоминание географической позиции. Target — уклон через **300 м**, привязанный по расстоянию, а не по фиксированному номеру строки.

Валидация — последние 25% допустимых примеров без shuffle. Из обучения исключаются примеры, чьи будущие targets достигают валидационного участка, и добавлен зазор на лаги. После оценки production-модель переобучается на всех допустимых парах исходного маршрута и прогнозирует по восстановленному профилю. Это **модель конкретного известного маршрута**, не доказанная способность предсказывать неизвестные дороги. На слишком коротком маршруте явно включается fallback текущего уклона, статус не утверждает готовность ML.

Результаты поставляемого маршрута:

| Модель | MAE | RMSE | R² / детали |
|---|---:|---:|---|
| Восстановление / ExtraTrees | 6,75 м | 9,31 м | 152 валидационные точки |
| Прогноз уклона / RandomForest | 5,45 процентного пункта | 7,04 процентного пункта | −0,131; 297 валидационных точек |

Для сравнения, простое сохранение текущего уклона даёт MAE 6,04 п.п. на той же валидации. ML немного улучшает MAE относительно этого простого метода, однако отрицательный R² указывает на ограниченное качество прогноза. В интерфейсе показано `низкая точность`; метрики не скрываются. Один короткий неоднородный маршрут и шумный DEM недостаточны для надёжной модели. Это валидация на последней части маршрута, а не независимое внешнее испытание. Для серьёзной оценки нужны отдельные маршруты, которых не было при разработке.

## Сравнение исходных и прогнозных данных

Исходный профиль хранится отдельно в `RouteBundle.original` и `route_original.csv`. Он не подменяется восстановленными значениями и не передаётся модели как скрытый ответ.

- **Высота:** синяя линия — исходная сглаженная высота из DEM; золотая пунктирная — профиль после ML-восстановления; золотые точки — восстановленные пропуски.
- **Уклон:** синяя линия — исходный уклон; фиолетовая пунктирная — прогноз ML. Значение, предсказанное в позиции `d`, рисуется в позиции **`d + 300 м`**, поэтому сравнивается с реальным уклоном в правильной точке.
- Зелёная линия — пройденная часть профиля симуляции, вертикальная — текущая позиция. Легенды показывают назначение линий. При сбросе сравнительные линии сохраняются, пройденная часть очищается.

«Исходные» означает данные Open-Meteo, обработанные описанным выше причинным сглаживанием, а не измерения дорожного датчика. Высоты на мостах и в тоннелях могут отличаться от поверхности дороги.

## Прохождение поворотов

Кривизна оценивается по полной геометрии OSRM с шагом 10 м и пространственным окном ±20 м. Для трёх точек рассчитывается радиус описанной окружности. Ограничение скорости определяется боковым ускорением: `v = sqrt(a_lat × R)`, где `a_lat = 1.3 м/с²`. Для устойчивости демонстрации нижняя граница на поворотах — 10 км/ч, верхняя — 90 км/ч; это оценка по геометрии, не сертифицированное ограничение безопасности.

Обратный проход по маршруту рассчитывает допустимую скорость подхода из тормозного пути `v_before² ≤ v_curve² + 2 × a_brake × distance`. Поэтому машина тормозит **до** поворота и разгоняется после него с ограниченным ускорением. Ограничение работает в обоих режимах. Значение 30–90 км/ч в ручном поле задаёт желаемую скорость на прямой; на крутом повороте фактическая скорость может быть ниже 30. Текущее ограничение по поворотам показано под картой. Параметры находятся в settings; коэффициенты сцепления и дорожные знаки не моделируются.

## Физическая модель расхода и оптимизация

ML не используется для расхода. Для `v = speed_kmh / 3.6`, `θ = atan(slope_pct / 100)`:

```text
F_roll  = m × g × Crr × cos(θ)
F_grade = m × g × sin(θ)
F_air   = 0.5 × rho × Cd × A × v²
F_acc   = m × acceleration
P_kW    = max(0, (F_roll + F_grade + F_air + F_acc) × v / 1000)
fuel_Lh = idle_Lh + P_kW / (efficiency × diesel_kWh_per_L)
fuel_L100km = fuel_Lh × 100 / speed_kmh
fuel_used_L += fuel_Lh × dt / 3600
```

Ниже 1 км/ч отображаются L/h. На спуске отрицательная тяговая мощность ограничивается нулём; остаётся расход холостого хода. Параметры: g=9.81, rho=1.225, Crr=0.008, Cd=0.65, A=7.5 м², КПД=0.38, дизель=9.8 кВт·ч/л, idle=1.5 л/ч.

Оптимизатор перебирает скорости 30…90 км/ч с шагом 1. Стоимость:

```text
J = (0.4 × current_fuel_L100km + 0.6 × predicted_fuel_L100km) / 30
    + LAMBDA_TIME × 60 / speed_kmh
    + POWER_PENALTY × max(0, predicted_power_kW / 210 - 1)²
```

Штраф времени балансирует топливо и длительность; штраф мощности заранее снижает желательную скорость при большом подъёме. `LAMBDA_TIME`, `POWER_PENALTY` и остальные коэффициенты находятся в settings. Результат сглаживается ограничением скорости изменения; фактическое ускорение/замедление ограничивается отдельно. В последних 300 м оптимизатор использует текущий уклон вместо прогноза за пределами маршрута.

## Ограничения демонстрационной модели

- DEM описывает поверхность местности, а не дорожное полотно на мосту или в тоннеле. На горных дорогах, особенно после восстановления, возможны заметные ошибки уклона. Сырые данные сохранены для проверки.
- Не моделируются светофоры, пробки, ограничения скорости отдельных участков, передачи, тяговая характеристика двигателя, сцепление, ветер, рекуперация и полноценная динамика тормозов. Мощность входит в штраф оптимизации, а не в жёсткий физический предел тяги.
- Рекомендации не являются указаниями для реального водителя; 30–90 км/ч — демонстрационный диапазон. Расход не калиброван на конкретный грузовик.
- ML обучается на маленьком наборе. Его фактическое качество отражено выше и в интерфейсе. Отрицательный R² не приводит к остановке приложения.
- Сам маршрут работает offline из поставки. Новые дороги/высоты и новые тайлы требуют доступа к соответствующим публичным сервисам.
- Длина нового маршрута ограничена 10 000 точками профиля; измените шаг или лимит в settings при необходимости. Закрытие во время запроса может ждать его timeout и оставшиеся попытки.

## Проверки

```bat
python -m pytest
python -m compileall .
python -m pip check
python main.py --smoke-test
```

GUI smoke test открывает настоящее окно, проверяет стрелку скорости и сравнительные кривые, нажимает Старт/Паузу/Сброс, проверяет очистку графика, ускоренно проходит маршрут целиком, проверяет JavaScript-состояние Leaflet и положение в B, сохраняет снимки/JSON в `artifacts/`, затем закрывает окно. Это отдельная проверка, обычный запуск не закрывает приложение автоматически.

На headless Linux: `QT_QPA_PLATFORM=offscreen python main.py --smoke-test`, если системные библиотеки WebEngine допускают offscreen. Некоторые окружения требуют виртуальный дисплей (Xvfb); это ограничение окружения, а не бизнес-логики. Sandbox WebEngine по умолчанию не отключается.

## Решение проблем

| Проблема | Решение |
|---|---|
| `python`/`py` не найден | Установите Python с Add to PATH; в уже подготовленном проекте используйте `.venv\Scripts\python.exe` |
| Нет PySide6 или sklearn | Установите requirements именно интерпретатором текущей `.venv` |
| PowerShell запрещает activate | Запускайте `.venv\Scripts\python.exe` напрямую |
| Нет интернета / API timeout | Используется локальный маршрут; строка состояния показывает fallback; повторите ПОСТРОИТЬ МАРШРУТ позже |
| Пустой или повреждённый CSV | Приложение пробует API, затем `data/demo`; при необходимости скопируйте оттуда три исходных файла в `data` |
| Карта без подложки | Проверьте доступ к tile.openstreetmap.org; симуляция и локальные линии работают без тайлов |
| Карта чёрная / WebEngine GPU issue | Обновите графический драйвер; для диагностики в PowerShell задайте `$env:QTWEBENGINE_CHROMIUM_FLAGS='--disable-gpu'` перед запуском |
| Не записывается CSV | Закройте этот CSV в Excel и проверьте права на `data`; ошибки сохраняются в лог |
| Медленный/неудачный прогноз | Изучите `ml_metrics.json`; слабая точность этого демонстрационного набора ожидаема и явно отображается |
| Не видны нижние кнопки | Увеличьте окно или прокрутите правую панель |

Основной журнал — `logs/application.log`, с ротацией. Для диагностики прикладывайте этот файл и фактический traceback, не удаляя исходный маршрут.
